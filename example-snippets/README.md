# Example Snippets

This directory hosts illustrative example snippets for:

> M. A. Cerny and J. Schneider, "Context-Aware Semantic Normalization in Heterogeneous BIM Data."

To keep the published article concise, the full-length example artifacts are
reproduced here rather than in the paper. The paper points readers to this
repository through the Data Availability Statement.

All snippets are drawn from a single representative model with project-identifying
values anonymized using generic structural placeholders (e.g., `FamilyA:TypeA_1`).
IFC class names, relationship types, attribute keys, and schema-level terms are
reproduced verbatim, as they are part of the public IFC standard and carry no
project-specific information. The snippets show the structure of the pipeline
outputs, not literal runnable data.

The snippets are organized by the pipeline stages of the system overview (Figure 1
of the paper): Context Extraction and Retrieval and Normalization.

---

## Context Extraction

These artifacts correspond directly to the output of the Context Extraction stage
(Section 3.2 of the paper) and illustrate the inputs received by the LLM reasoning
pipeline. They are generated by the schema serialization procedure implemented in
[`src/serialization.py`](../src/serialization.py) and can be regenerated for any
syntactically valid IFC file:

```bash
python run.py path/to/model.ifc IfcFlowSegment
```

### Paths

The table below lists the schema path groups produced for a representative model in
which the seed class is IfcFlowSegment for which one entity type existed:
IfcPipeSegmentType. Each row corresponds to one JSON summary file. Hop denotes graph
distance from the seed.

| ID | Hop | Traversal chain | Target class | Summary file |
|----|-----|-----------------|--------------|--------------|
| P1 | 1 | IfcFlowSegment → IfcRelDefinesByType → | IfcPipeSegmentType | [`P1_IfcPipeSegmentType.json`](context-extraction/schema-summaries/P1_IfcPipeSegmentType.json) |
| P2 | 1 | IfcFlowSegment → IfcRelDefinesByProperties → | IfcPropertySet | [`P2_IfcPropertySet.json`](context-extraction/schema-summaries/P2_IfcPropertySet.json) |
| P3 | 1 | IfcFlowSegment → IfcRelAssignsToGroup → | IfcSystem | [`P3_IfcSystem.json`](context-extraction/schema-summaries/P3_IfcSystem.json) |
| P4 | 2 | IfcFlowSegment → IfcRelDefinesByType → IfcPipeSegmentType → IfcRelAssociatesMaterial → | IfcMaterial | [`P4_IfcMaterial.json`](context-extraction/schema-summaries/P4_IfcMaterial.json) |

The structural organization of the summaries, including nesting, grouping by
property set name, and null entries, reflects the actual output of the schema
serialization procedure without modification.

## Retrieval and Normalization

These artifacts trace the Retrieval and Normalization stage (Section 3.3 of the
paper) for the material concept, applied to the same representative model. They were
produced by the GPT-5 mini reasoning stage and illustrate a recovery case in which
the most informative material signal is retrieved from a non-normative schema
location.

### Localization

One localization call is issued per path group. The prompt instructs the LLM to
return up to three schema paths containing evidence for the material concept, ranked
by informativeness.

| Path group | Localization output |
|------------|--------------------|
| P1 (IfcPipeSegmentType) | [`localization_P1.json`](retrieval-and-normalization/localization/localization_P1.json) |
| P2 (IfcPropertySet) | [`localization_P2.json`](retrieval-and-normalization/localization/localization_P2.json) |
| P3 (IfcSystem) | [`localization_P3.json`](retrieval-and-normalization/localization/localization_P3.json) — returns `None`; IfcSystem carries no material-relevant information |
| P4 (IfcMaterial) | [`localization_P4.json`](retrieval-and-normalization/localization/localization_P4.json) |

### Reranking

Candidates from all paths are merged into a single set and submitted to the
reranking prompt. The LLM assigns a new global rank based on informativeness,
compactness, and semantic appropriateness of the schema location. The reranking
output is provided in
[`reranking.json`](retrieval-and-normalization/reranking.json). The 06 Werkstoff
attribute from P2 is promoted to rank 1, surpassing the normative IfcMaterial.Name
from P4. This demonstrates the recovery mechanism of material semantics from a
non-standard schema location. P3 is excluded as it returned None.
